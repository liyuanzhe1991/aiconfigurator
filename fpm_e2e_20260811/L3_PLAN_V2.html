L3 精度评测方案 v2

2026-08-12 · 适用:GLM5.2@B200、MiniMax-M2.7@H100/H200 多并行战役,及此后的所有"采集建模 vs 真实"评测 · 依据:fpm-all-20260811 战役全部实测教训(证据见 LEDGER.md)

0. 定位与原则

精度评测的唯一判据是 L3:真实流量下每个调度步的 FPM 流实测墙钟 vs 模型在该步精确坐标上的预测。 L0(查表位精确)是免费的上线前自检;L2(self-benchmark 显式点)只作 gap 归因/debug 与 modeling 改动的回归 oracle,不进精度报告正文。
  • 配置一致性是前提且必须主动验证:采集 cell / serve 栈同镜像、同 engine args(capture 面、调度模式、prefix caching);每个流量段用"纯步对时"核验(与采集同坐标 ±3% 才放行)。
  • ground truth 只认 FPM 流逐步实测;客户端 TTFT/TPOT 仅交叉参考,永不作判据。
  • 统计禁止正负相抵;全点位表必出;已知固有地板如实标注、禁止常数补偿。

2. 三分层框架(每个 cell 的测试集结构)

层定义验证什么归属判定
A采集点步坐标(或 mixed 的分量坐标)精确命中 parquet 行数据保真 vs 真实(全零 bug 属于这层) 生成器对着 parquet 逐点程序断言(assert on_grid == expected),人不判
B域内离网域内但无采集行插值 vs 真实
C域外外插仅 prefill bs 轴:bp > 采集上限 Bc新增的 bs 外插功能
外插边界(硬规则):C 组只存在于 prefill(及 mixed 的 prefill 分量)。decode 的 B 轴严格域内, 不生成任何 decode 外插窗;模型在 B > 采集最大批处照旧拒答。

3. prefill 矩阵(burst 法)

3.1 制造方式

一次性齐发 bp 条等长随机 token 请求,约束 bp × tok ≤ max_num_batched_tokens ⇒ 整个 burst 落在 同一个调度步,坐标 = (bp, bp×tok, 0),FPM 流逐步可读。每格 20 次 burst 取中位。

3.2 点位推导规则(零手写常数,输入 = parquet + resolved-config)

参数推导规则
锚点 bp(A 组)= 采集格里的全部 bs 值(逐行)
外插 bp(C 组){1.5, 2, 3, 4, 6, 8, 12, 16} × Bc,截断于 min(max_num_seqs, 预算/tok);误差按 bp/Bc 倍数分层
tok 档burst 总量落在 capture 边界(悬崖对导出)的 {0.5, 0.9, 1.1, 2, 4}× 处,截断于预算;对齐采集 token 格以复用锚点
B 组(域内离网)tok = 相邻采集档中点(bp ≤ Bc);每对相邻档 ≥1 样本
prefix 子矩阵bp ∈ {1.5Bc, 2Bc} × tok 中档 × prefix = prefix 格 1/4、3/4 分位;可行性 tok+prefix ≤ max_model_len − block
引擎配置与 prefill 采集 cell 严格同参(sync 调度 + 采集 capture 面 + prefix caching ON);burst 用随机 prompt 避免跨请求前缀命中。

4. decode 矩阵(窗口法,无外插)

4.1 A 组命中由算术保证

并发 C = 采集批值的窗口内,每步 KV 总量恰好递增 C;采集行总量都是 C×s ⇒ 窗口 KV 扫过的区间内, 每个采集 s 值被真实步精确命中一次。生成器只需保证窗口 [isl, isl+osl] 覆盖目标 s 值。

4.2 点位推导规则

参数推导规则
B 阶梯采集批格分位数(A 组)+ 悬崖对邻域 B*、B*±邻近整数 + eager 段中点(B* 与最大采集批之间,B 组)
KV 带每请求 s = 该批曲线覆盖的 {1/6, 1/3, 1/2, 2/3, 5/6} 分位(A 组扫过命中 + 分位间自然产生 B 组步);上限尊重 max_model_len
巨 KV 标记KV 总量 ≥ 该 cell KV 域上四分位的窗 → 强制多启动(≥3)取中位(档位抽签地板,LEDGER 七启动判别)
off-capture 批次真实流量本身在批次间迁移,逐步打分自然覆盖;不设专窗

5. mixed 矩阵(分量分层)

parquet 无 mixed 行;模型值 = pre(bp, chunk+Bd, kvp) + max(0, dec(Bd,kvd) − base(Bd))。分层对分量坐标做:

层构造意义
Achunk = 采集token档 − Bd(使 chunk+Bd 恰落采集行)且 Bd = 采集 decode 批值,kvd 由池算术命中纯公式误差——插值完全排除。验收门挂这里
Bchunk = 档间中点等,任一分量走插值公式+插值联合误差(参考)
Cbp ∈ {2, Bc, 1.5Bc, 2Bc} 条短 prompt 齐发 + 稳定 decode 池(bp×tok + Bd ≤ 预算)bs 外插在组合公式里的表现;bp > Bc 时标 C,不混入 B 组统计

5.1 覆盖轴

  • 跨 regime 对必含:chunk+Bd = capture 边界 ±ε(公式主战场);
  • kvp:isl = k×chunk(k∈{2,4}),窗口内 chunk 步自带递进 kvp,逐步打分覆盖;
  • kvd:decode 池 ISL 取 decode KV 域两档分位;
  • Bd:采集 decode 批格分位子集。

5.2 驱动修复(bd64 零稳态步的教训)

池先行:ignore-eos 长 OSL 请求先灌满并稳定 decode 池 → chunked prefill 请求限速逐条注入; 稳态判据 = (bd == 池标称 且 tp == chunk);每窗稳态步 n ≥ 15,不足自动延窗。
已知公式残差(graph 侧 marginal 重复计费 +8~15%、eager 侧纯行超估 ×1.13~1.16;LEDGER 严格验证章)—— modeling 更新若未修,A 组会如实显出,按"已知问题复现"记账;修了,A 组即其验收。

6. 指标(统一定义)

每个评测格:  APE = |model − measured_median| / measured_median   (附窗内 IQR 与稳态步数 n)
每层每相位:  MAPE = mean(APE)
             P95 APE = 95 分位(报出发生坐标:完整五元组 bp/tp/kvp/Bd/kvd 或 (b, s))
             MAX APE = 最大值(报出发生坐标)
C 组另出:    误差 vs 外插倍数(bp/B_c ∈ ≤2×, 2-4×, 4-8×, 8-16×)分层曲线
  • 全点位明细表必出(每格:坐标、实测中位、IQR、n、模型值、APE、层标签);
  • 点集 n < 20 时 P95 注明实际含义(≈次差点);
  • 临时门(终值由用户定):prefill C 组 ≤2× 外插 MAPE ≤ 10%,更远只记录;mixed 门挂 A 组。

8. 矩阵生成器规范(make_l3_matrix.py)

输入:  parquet(该 cell)、resolved-config dump(采集工件现成)
输出:  burst 计划 + 窗口计划 + mixed 计划(每点带层标签与可行性证明)
       coverage_report.json(每层每轴配额达成情况)
断言:  每点层归属 assert 对 parquet;可行性(预算/max_model_len/max_num_seqs/块对齐)
失败:  任一配额不满 ⇒ 生成失败不发车。配额:
       A 组 — 采集格值覆盖率 ≥80%(decode 每批 ≥3 KV 深度;prefill 每 bs×每档 ≥1)
       B 组 — 每对相邻格值之间 ≥1 样本(大间隙不遗漏)
       C 组 — 每个外插倍数层 ≥2 个 tok 档,graph/eager 各有样本
